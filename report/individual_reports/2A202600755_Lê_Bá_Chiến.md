## II. Debugging Case Study (10 Points)

*Analyze a specific failure event you encountered during the lab using the logging system.*

- **Problem Description**: Khi cấu hình API chưa đúng hoặc provider chưa có key thật, chế độ `hybrid` có thể không tạo được LLM provider. Nếu không xử lý, ứng dụng sẽ lỗi ngay khi người dùng gửi câu hỏi từ web UI.
- **Log Source**: `src/retail/hybrid_advisor.py` ghi sự kiện `RETAIL_AI_FALLBACK` với `reason`, `provider`, `model`, `llm_steps`. Case này được kiểm chứng trong `tests/test_hybrid_advisor.py::test_hybrid_advisor_falls_back_when_provider_is_not_configured`.
- **Diagnosis**: Nguyên nhân chính là cấu hình môi trường, không phải dữ liệu retail. Provider factory cần phân biệt rõ API key thiếu, API key còn là placeholder, provider không hợp lệ và local model path thiếu. Với ReAct agent, các lỗi khác như parser error hoặc hallucinated tool cũng phải được coi là AI path không tin cậy.
- **Solution**: Tôi tham gia sửa hướng xử lý bằng cách để `ProviderConfigurationError` báo lỗi rõ ràng, `HybridRetailStockAdvisor` bắt exception trong chế độ hybrid, ghi fallback reason vào metrics và chuyển sang base rules. Đồng thời bổ sung test cho các tình huống: thiếu provider config, parser error, hallucinated tool, timeout, base mode không gọi LLM và strict LLM mode không fallback.

## III. Personal Insights: Chatbot vs ReAct (10 Points)

*Reflect on the reasoning capability difference.*

1.  **Reasoning**: Khối `Thought` giúp agent chia câu hỏi tồn kho thành các bước có kiểm chứng: lấy tồn kho, xem lịch sử bán, tính nguy cơ hết hàng, tính số lượng nhập lại và tìm hàng bán chậm. Chatbot trả lời trực tiếp dễ đưa ra nhận định cảm tính, còn ReAct buộc câu trả lời dựa trên `Observation` từ tool.
2.  **Reliability**: Agent có thể tệ hơn Chatbot khi provider cấu hình sai, model trả sai format `Action`, gọi tool không tồn tại hoặc mất quá nhiều thời gian. Vì vậy chế độ `hybrid` cần fallback về rule-based advisor, còn `llm` strict mode phải báo lỗi rõ thay vì âm thầm trả kết quả không đáng tin.
3.  **Observation**: Observation làm cho bước sau cụ thể hơn. Ví dụ sau khi `get_inventory` trả tồn kho và category, agent có thể gọi `detect_stockout_risk` hoặc `recommend_reorder_quantity` cho sản phẩm phù hợp thay vì tự đoán. Trace trên UI cũng giúp nhóm kiểm tra agent đã dùng dữ liệu nào trước khi đưa ra khuyến nghị.

## IV. Future Improvements (5 Points)

*How would you scale this for a production-level AI agent system?*

- **Scalability**: Tách hàng đợi xử lý request AI bất đồng bộ, cache dữ liệu inventory/sales theo phiên và chuẩn hóa cấu hình provider để có thể chuyển nhanh giữa OpenAI, Gemini, DashScope/Qwen và local model.

- **Performance**: Theo dõi latency/token theo từng provider, đặt timeout thấp hơn cho UI, dùng fallback sớm khi provider chậm và bổ sung dashboard metrics để so sánh `base`, `llm`, `hybrid` trong các test case cố định.
